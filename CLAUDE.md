# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

MyBookShelf is a personal reading journal: an Express 5 + PostgreSQL API with a React + TypeScript frontend (Vite), deployed on Vercel.

## Commands

```bash
npm run dev               # one server: API + React app with instant reload -> http://localhost:3000 (PORT overrides)
npm run build:client      # build the React app into public/ (commit the result, see Deployment)
npm start                 # node server.js: API + the built site in public/
npm run typecheck:client  # TypeScript check of client/
npm run migrate           # apply pending migrations/*.sql (local DB, or Neon if DATABASE_URL is set)
node testGoogleBooks.js   # sanity-check GOOGLE_BOOKS_API_KEY
```

There is no linter. Check backend syntax with `node --check <file>`; the frontend is checked by `npm run typecheck:client`. `npm run dev` runs `server.js --dev`: Vite runs inside Express (middleware mode, kept away from `/api`, never loaded in production), so there's one server and one port. `nodemonConfig` ignores `client/` and `public/` (Vite reloads those itself).

End-to-end tests: Playwright + TypeScript in `e2e/` (`npm run test:e2e`, `npm run typecheck:e2e`, `npm run test:e2e:report`). The config runs `npm run build:client` first (so `public/` is fresh afterwards) and starts its own server on port 3210 against the **local** database and refuses to run if `DATABASE_URL` is set. **Testing is local only; it never spends cloud credits.** The config starts the server with `BLOB_READ_WRITE_TOKEN`, `GOOGLE_BOOKS_API_KEY` and `SMTP_HOST/USER/PASS` blanked (an empty value wins over `.env`), so tests never touch Vercel Blob, the Google Books quota or real email. Don't add tests or scripts that reach Neon, the live site or any other paid service. In the browser, `fixtures.ts` blocks every request that isn't to the local server, including Google Fonts and Google cover images, so pages use fallback fonts. Any extra browser context a test opens must call `blockExternal(context)`. `e2e/localOnly.spec.ts` fails if anything gets out. Account deletion used to call Blob `list()`, a paid "advanced operation" (2,000/month on Hobby), and test runs used up a month's quota. `e2e/noBlob.spec.ts` fails if the token ever reaches the test server; the "Cover upload failed: BLOB_READ_WRITE_TOKEN is not set" line in the test output comes from that check. Each test signs up a throwaway `@example.test` account and deletes it afterwards (sign-up and deletion retry once on a dropped keep-alive connection, ECONNRESET, which happens under heavy parallel load). Tests may take up to 60 s; there are no automatic retries, so a flaky test gets fixed rather than hidden. To shake out races, run `npx playwright test --repeat-each=5 --workers=8`.

Running migrations against production (PowerShell). The owner runs these, not Claude. Before running, take a Neon snapshot branch (Neon console > Branches > Create branch from `main`). Delete the snapshot about a week later if nothing went wrong. If something breaks, fix it forward with a new migration; restore the snapshot only if real data was lost.
```powershell
$env:DATABASE_URL = "<neon connection string>"; npm run migrate; Remove-Item Env:DATABASE_URL
```

## Environment

`.env` (never committed; see `.env.example`): `DB_USER/DB_HOST/DB_NAME/DB_PASSWORD/DB_PORT` for local Postgres, or `DATABASE_URL` for Neon (it wins when set). Also `JWT_SECRET`, `GOOGLE_BOOKS_API_KEY`, `BLOB_READ_WRITE_TOKEN` (Vercel Blob, **public** store), and `SMTP_HOST/SMTP_PORT/SMTP_USER/SMTP_PASS/MAIL_FROM` (Gmail app password; in dev without SMTP the reset email is logged as `[mail:dev]`). `APP_URL` optionally overrides the link base in emails.

## Deployment

- **The built site is committed.** Vercel serves an Express project's static files only from `public/` (it ignores `express.static`), and its zero-config Express setup has no build step. So `public/` holds the Vite build of `client/` and is committed. **Run `npm run build:client` (or the tests, which build first) before committing any frontend change**, or the live site keeps the old build. Never edit `public/` by hand; it's emptied on every build. The build is reproducible (same code, same files), so a rebuild without changes shows no diff. There is deliberately no `build` script (Vercel would try to run it).
- Vercel deploys **only `main`** (production). `vercel.json` disables deployments for `dev` (`git.deploymentEnabled.dev = false`). Work happens on `dev` and is merged into `main` to release.
- **Git rules:** never `git push`, and never merge `dev` into `main`. The owner does both. Commit only when asked.
- Migrations are **not** run automatically. Run new `migrations/*.sql` against Neon before merging to `main`, or the live site breaks on missing columns.
- `server.js` exports the app for Vercel and only calls `listen()` when `NODE_ENV !== "production"`.
- Security headers (HSTS, CSP `upgrade-insecure-requests`, nosniff) are set in **both** `vercel.json` (static pages) and Express middleware (API), because on Vercel static files don't pass through Express.
- Vercel limits request bodies to ~4.5 MB; uploads are capped at 4 MB.

## Backend architecture (`server.js`, `src/`)

- `routes/*` -> `controllers/*` -> `pool` from `config/db.js`. Responses are `{ status, message, data }`. Unknown `/api` routes get JSON 404; a central error handler turns Multer errors into 400s.
- `config/db.js` sets a pg type parser so `DATE` columns come back as `"YYYY-MM-DD"` strings (prevents off-by-one-day bugs).
- **Migrations**: `scripts/migrate.js` applies `migrations/NNN_*.sql` in filename order, each in a transaction, recorded in `schema_migrations`. Add a new numbered file; never edit an applied one.
- **IDs**: every table's `id` comes from a database sequence (`users`/`books` since migration 008; they used to be `Date.now()`, which collided). Never set `id` in an INSERT.
- **Auth/session**: login sets an HttpOnly JWT cookie (`utils/session.js`; `__Host-mbs_session` in production, `mbs_session` locally). The token carries `tv` (session version). `middleware/authMiddleware.js` checks it against `users.token_version`; a password reset increments that column, which signs the user out everywhere. `sameOriginOnly` rejects cross-site POST/PUT/PATCH/DELETE (CSRF). Emails are stored lower-case and compared case-insensitively.
- **401 has a side effect**: the frontend treats any 401 as "session over" and logs out. Use 400 for things like a wrong password on account deletion.
- **Books**: `bookController.parseBook` validates every field and maps camelCase input to snake_case columns (`COLUMNS`). `PUT /api/books/:id` is a **full replacement**, so the client must send every field. An increased `current_page` inserts a `reading_activities` row. `genre` and `completed_at` are legacy columns kept in sync.
- **Covers** (`services/coverStorage.js`): uploads go to Vercel Blob at `covers/<userId>/<uuid>.<ext>`. The image type is sniffed from the bytes. Old covers are deleted when replaced or when the book or account is deleted, but only files that `isOwnedCover()` confirms are in this store **and** this user's folder. Google Books cover URLs are stored as-is and never deleted. Never call Blob `list()` (or anything else billed as an advanced operation) on a routine path: account deletion deletes the covers its books point to (`DELETE ... RETURNING cover_url` then `deleteUnusedCovers`; `del` is free). Uploads that were never saved to a book stay in the store. Cloudinary is gone: the account was closed and migration 006 cleared its old links. Don't add Cloudinary code back.
- Password reset (`passwordResetController.js`): SHA-256-hashed single-use tokens, 1-hour expiry, 60 s resend throttle, always a generic reply. Email links never use the request's Host header.
- The Google Books search endpoint requires login (it spends the API key quota).

## Frontend architecture (`client/`)

React 19 + TypeScript, built by Vite (`client/vite.config.ts`) into `public/`. No router, state or CSS libraries. The app moved from vanilla JS in November 2026 keeping the same markup, classes, roles and labels, so the look and the tests carried over unchanged (a pixel comparison of every page at phone, tablet and desktop sizes matched). Keep it that way: the e2e tests find things by role, label and class.

- **Pages** (Vite multi-page build, `rollupOptions.input`): `index.html` (the app, `src/main.tsx`), `login`/`register`/`forgot-password`/`reset-password.html` (one entry, `src/auth.tsx`, page picked by `#root[data-page]`; `features/auth/AuthPages.tsx`), `privacy`/`terms.html` (static text; `src/legal.ts` only loads the CSS). `client/public/` (favicon, `js/theme-boot.js`) is copied as-is. URLs are unchanged from the vanilla app (`/index.html#/...`, `/login.html`, …).
- **Routing**: hash routes (`#/dashboard`, `#/library`, `#/physical`, `#/book/:id`, `#/authors`, `#/author/:name`, `#/series`, `#/series/:name`, `#/challenges`, `#/challenges/:id`, `#/statistics`; old `#/stats` and `#/home` redirect). `app/useHashRoute.ts` parses the hash and decodes the id once (a malformed id becomes "", i.e. not found); `app/routes.ts` names routes and nav tabs; `app/App.tsx` boots (loads everything once, syncs the theme, connects `onBookFinished` to the unlock prompt), sets the tab title (a book/author/series/challenge page uses its name) and renders the page. "n" adds a book and "l" logs reading from anywhere outside text fields.
- **`src/api/`**: `client.ts` fetch wrapper (any 401 logs out; see the backend notes), `index.ts` every endpoint, `types.ts`, `mappers.ts` (`normalizeBook`/`toPayload`). `toPayload` is typed against `Book`, so a field added to `Book` and not sent is a compile error. When you add a book field, update `parseBook` + `COLUMNS` (server), `Book` in `types.ts`, and `normalizeBook` + `toPayload`.
- **`src/store/`**: one state object (books, activities, statistics, `activityVersion`, goals, custom goals, challenges, Next Up, `loaded`/`loadError`) and the mutations (`createBook`, `updateBook`, `deleteBook`, goals, challenges, `assignSpots`, `saveNextUp`, …), which call the API and then replace state. **State is replaced, never mutated.** Read it with `useStore(selector)`; the selector must return something already in the state (or a primitive), and derived lists are built with `useMemo` in the component. `getState()` reads it outside React (event handlers, dialogs). A book added while the first load is still on its way is kept when the load lands.
- **`src/domain/`** (pure, takes data as arguments, no React): `readingRules` (`applyReadingRules`: auto Reading/Read status, start/finish dates, page clamping; `percent`, `tagOptions`, `booksFinished`), `shelf` (**authors and series are derived** from books, no tables: `authorNames` splits co-authors on `,`/`&`; `seriesList`/`summarizeSeries`, `seriesHasRoom`, `seriesChoicesFor`, `canonicalSeriesName`), `goals` (`goalProgress`, `goalTitle`, `streakRun`/`readingStreak`), `challengeMatch`, `quote`, `dates` (`today()` = the reader's local date), `constants`.
- **`src/components/`**: `Modal` (a `<dialog>`; `onSubmit` returning `false` keeps it open, a thrown error shows in `.form-error`) with `openDialog((done) => <X onClose={done} />)` and `confirmDialog`; `toast`; `Icon`; `BookBits` (`Cover` with a title fallback, badges, stars, `Bookcase`/`ShelfBook` with the vine, `CoverStack`, `LoadingSkeleton`); `inputs` (`RateInput`, `MultiSelect`, `CheckCard`); `Tooltip` (`tooltipProps(text)` for chart marks); `format` (`fmt`, `stripHtml`, links, `seriesLabel`). React escapes text, so user data is never treated as HTML; `dangerouslySetInnerHTML` isn't used anywhere, keep it that way.
- **`src/features/<area>/`**: `library`, `book` (the book page), `books` (Add with Google search + manual, Edit details, Review, `SeriesFields`, `CoverPicker`, Google Books mapping), `physical`, `authors`, `series`, `dashboard` (+ `GoalDialog`), `journal` (Log your reading), `statistics` (+ `RecapCard`), `challenges` (pages, dialogs, templates, chips), `auth`, `theme`. Pages keep their search/filter/tab in module variables, so it survives visiting a book and coming back. `app/actions.ts` re-exports the app-wide actions (Add a book, Log your reading, the spot panel).
- **Series total** ("Books in series", `books.series_total`) belongs to the whole series: the server copies it to every book in that series (case-insensitive) on add/update, so a book saved with it empty clears it for the whole series; `createBook` inherits the series' total and Edit details fills it in, so the app's forms never do that by accident. With a total set, novellas (non-integer numbers) don't count toward "read X of N". The **Series field** in Add/Edit details is a combobox (`SeriesFields`) listing `seriesChoicesFor(books, book)`: series where `seriesHasRoom` (not Completed, and with a total, `missing > 0`; `onShelf`/`missing` come from `summarizeSeries`, which the Series page uses too) plus the book's own series. A typed name that's not a series offers "Create series"; any typed name is saved with `canonicalSeriesName` (case/whitespace-insensitive match to the existing spelling), so duplicates can't be created. Typing the exact name of a full/completed series still joins it (with a hint).
- **Custom goals** (`reading_goals` table, `/api/goals/custom`) and **challenges** (`challenges` table with a JSONB `items` list, `/api/challenges`, full-replacement PUT) are the only per-user tables besides books. Goal progress is computed client-side (`goalProgress`).
- **Smart challenges** (migration 010). A challenge has an optional date window (`starts_on`/`ends_on`) and `auto_match`; each spot (`items[i]`) has a `label`, optional `criteria` (genres, tropes, themes, settings, characters, title rule, author, age, format, pages, year; validated in `challengeController.parseCriteria`), a `bookId` and `assignedAt`. **All matching lives in `src/domain/challengeMatch.ts`** (pure, unit-tested in `e2e/matching.spec.ts`); never re-implement a rule elsewhere. A match is *confirmed* only from the book's own tags/facts; a word found only in the summary makes it *possible*, which is shown with its reason but never ticked or assigned automatically. Only **Read** books count toward a spot; an unread book in a spot is "planned" and completes by itself when finished. Finishing a book (`store.updateBook` -> `onBookFinished`) opens the "You unlocked challenge spots!" prompt (`openUnlockDialog`) so the reader confirms; deleting a book frees its spots (server + store). `features/challenges/`: `ChallengesPages.tsx` (dashboard + board), `ChallengeDialogs.tsx` (create with templates, spot rules editor, spot panel with ready/planned/possible matches and Google "Find new books", fill review, unlock prompt); the book page has a "Challenge spots" card. Prompts named after a colour get that colour on the board (`promptColour`).
- **Dashboard** (`features/dashboard/`, designed from the owner's sketch): Currently Reading / TBR / Completed, reading streak + month calendar, reading goals (yearly + custom goals), quote of the day, Next Up, Most Recent Entries. **Quote of the day** (`domain/quote.ts`): lowest hash of local date + quote wins, so it's random-looking but the same on every reload and device that day; today's pick is pinned in localStorage `quoteOfTheDay` so adding quotes mid-day can't swap it; yesterday's shown quote is skipped (the pinned one, else `replayedPick` replays two weeks so devices agree). The charts (books per month, genres, completion) and a summary row live on **Statistics**. The Book Shelf is the Library's default view (`Bookcase`, with a Shelf/Grid switch remembered in localStorage `libraryView`); its leafy vine with fairy lights (`.shelf-vine`) is `aria-hidden`, has `pointer-events: none` and sits in its own band above the first row, so it never covers the hearts or links.
- **Journal / "Log your reading"** (`features/journal/LogReading.tsx`, opened from the top bar, the dashboard, the book page and the "l" key): a session is saved by `updateBook(id, changes, { session: { date, note } })`; the server (`parseSession` in `bookController`) writes a `reading_activities` row with `session_date` and `note` when pages go up **or** a note is written. Exception: marking a To Be Read book as Read without a session (a book read in the past) logs nothing, so it never touches the streak. Deleting a book deletes its `reading_activities` rows in the same transaction (the FK alone is `ON DELETE SET NULL`). The streak and calendar come from `statistics.readingDays`. **Dates**: an entry without a picked date uses the browser's local date (sent as `localDate` on every book PUT, and as `?today=` for statistics), accepted only within a day of the server's UTC date (`src/utils/dates.js`), else `CURRENT_DATE`; the server runs in UTC, so never rely on `CURRENT_DATE` alone for the reader's day.
- **Journal notes on the book page** (`features/journal/JournalNote.tsx`, Reading progress card): a note is shortened to three lines until clicked; opened, it shows in full with **Edit** (a dialog) and **Delete** (asks first). `PUT /api/activities/:id/note` changes the note; `DELETE /api/activities/:id/note` removes it, but an entry that also logged pages keeps the row (only `note` becomes NULL), because the pages are reading history (streak, recap, totals); a note-only entry is deleted. Both check the owner (404 otherwise) and the store's `editEntryNote`/`deleteEntryNote` call `refreshActivity`, so the dashboard, streak and Recap follow.
- **Chapters** (migration 014, November 2026): `books.chapter_count` (1-999, "Chapters" in Edit details; chapters are numbered 1..N, no names) and `reading_activities.chapter`. In Log your reading a book with chapters shows a numbered chapter picker (optional; a dot marks chapters with notes; tap again to unpick); a picked chapter needs a note, and the server stores `chapter` only together with a note (`sessionChapter` in the book PUT, checked against the book's count). The book page's **Chapters card** (`features/book/ChaptersCard.tsx`, full width below the two columns; the Reading progress list leaves chapter notes out, showing only the pages of a chapter entry that also logged pages) lists every chapter, blank or with its notes (newest first, same `JournalNote` expand/Edit/Delete) and an "Add a note" that opens Log your reading with the chapter picked. It loads `GET /api/activities/book/:bookId/chapters` (all of that book's chapter notes; the store's journal only holds the latest 30) and refetches when `activityVersion` changes. Several notes per chapter are kept (each is a dated journal entry, so they count toward the streak and Recap). The chapter count can't go below the highest chapter that has a note, or be cleared while chapter notes exist (400 from `updateBook`); delete those notes first.
- **Reading Recap** (`features/statistics/RecapCard.tsx`, bottom of Statistics): a month calendar of days with journal entries and the picked day's entries (cover, pages, note, time logged). `GET /api/activities/recap?month=YYYY-MM` (days + totals + `firstDate`) and `GET /api/activities/recap/:date` (entries joined to the book for cover/author). Same `reading_activities` rows as the streak; the current-streak highlight comes from `streakRun`, never a second streak calculation. Fetches are cached in the module until `activityVersion` changes (bumped by `refreshActivity`). When a month arrow becomes disabled, focus moves to the other arrow. Reading duration isn't tracked.
- **Day rollover**: `useDayRollover` in `App.tsx` checks every 30 s (and when the tab becomes visible) and re-keys the dashboard and Statistics once the local date changes, never while a `dialog[open]` is showing.
- **Edit details fields (migration 013, November 2026)**: **Goodreads review** (`books.goodreads_url`, `goodreadsUrl`): only http(s) links on goodreads.com are kept (checked by `goodreadsUrl()` in `bookController` and `checkGoodreadsUrl` in `EditBookDialog`; "goodreads.com/..." gets https:// added), opened with `target="_blank" rel="noopener noreferrer"`. **Re-read** (`is_reread`, `isReread`): a checkbox and a badge. **Age Demo** (`age_demos TEXT[]`, `ageDemos`): several per book; the app offers Young Adult, New Adult and Adult (`AGE_DEMOS`); Children and Middle Grade are still accepted (older books have them) and show on such a book until unticked; `age_category` is kept as a legacy copy of the first value (its CHECK constraint allows NULL or the five values). **Setting** (`setting TEXT`): free text; the old `settings` tags were joined into it and are no longer written. Challenge Setting rules match a word in that text (confirmed, reason "Setting: Island"). **Themes & keywords and Characters** are no longer edited or shown: the server stopped writing them (not in `COLUMNS`), existing values stay in the database and still count for older challenge rules, and the spot rules editor keeps such rules when saving. **Deleting categories**: `users.hidden_tags` JSONB (`GET/PUT /api/tags/hidden`, `tagController`), for genres, sub-genres, tropes and content warnings. "Edit list" in a tag list deletes a choice from the reader's list only: books that have it keep it (and it shows, ticked, when editing them), `tagOptions(books, kind, hidden)` leaves it out everywhere else, and typing it again restores it in its own spelling.
- **Physical Books** (`features/physical/`, `#/physical`, the last nav tab): books with `books.is_physical` (migration 012; `isPhysical` in the client), set by the "Physical book" checkbox in Edit details and the manual Add form. Its own search, status filter and sort on the same bookcase; the book page shows a "Physical book" badge linking to it. It's separate from Format and Ownership on purpose: the reader decides. The phone's bottom bar holds seven tabs; labels may wrap to two lines (`mobile.spec.ts` checks each one fits).
- **Next Up**: `users.next_up` (max 3 book ids, `/api/next-up`); only books still To Be Read are shown (`nextUpBooks`), so starting a book frees its slot.
- **Covers** in the browser: `CoverPicker` shrinks a picked image to at most 600×900 WebP/JPEG before uploading (one Blob operation per upload, only when the dialog is saved).
- The login state in the browser is just `localStorage.user` (name/email, used only for display; each page's `<head>` redirects on it before React loads). The token itself is never readable by JS.

## Theming and colours

- All colours are CSS custom properties in `client/src/styles/style.css` (one global stylesheet, imported by each entry) (`:root` = the default "cream" theme, built on the owner's palette #D8A2A2 rose, #FFDCDC blush, #FFF9D6 cream, #8EA66B sage; fonts Fraunces + Nunito Sans). Presets override them in `:root[data-theme="blush|sage|lavender|night"]`. Token names are roles: `--rose`/`--blush` = main accent, `--sage` = progress/"read". Use tokens (`--text`, `--muted`, `--surface`, `--rose-deep`, …), not hardcoded colours. The tokens have been tuned for WCAG AA contrast across all themes.
- **Responsive layout** (audited November 2026 at 320, 375, 430, 768, 900, 901, 1024, 1239, 1240, 1280, 1366 and 1920px; `e2e/responsive.spec.ts` guards it). Navigation by width (the "Navigation by screen width" section of `style.css`): up to 900px the tabs are the bar fixed at the bottom; 901–1239px a compact top row (brand badge only, "Log your reading" as its pen icon); 1240px+ the full row, in a top bar up to `--maxw` + 120px wide; up to 360px the bottom tabs show icons only (names stay for screen readers via `.tab-label`) and the brand shows its badge. Adding a nav tab means re-checking those widths. Long unbroken words: `body { overflow-wrap: break-word }`, headings use `anywhere`, and flex/grid children holding names get `min-width: 0` (the list is next to that rule); a page must never scroll sideways. Date fields on iPhone/iPad Safari get `appearance: none` + `min-width: 0` inside `@supports (-webkit-touch-callout: none)` (iOS only): its native date field otherwise ignores `width: 100%` and sticks out of narrow forms; Playwright's WebKit on Windows doesn't draw iOS controls, so check that one on a real iPhone. Text buttons/links get a 24px tall hit area through padding with matching negative margin (no visual change). The Reading Streak card stacks its pill above the calendar through a container query when the card itself is under 176px wide.
- Botanical decorations are CSS masks (`--sprig`, `--leaf-icon`) coloured by `--leaf`/`--sage`, on pseudo-elements only (body corners, page titles, dashboard cards, empty states, auth card), so they never touch the DOM. Don't put `backdrop-filter`/`transform`/`filter` on `.topnav`: it would become the containing block for the fixed mobile tab bar.
- The preset list exists in four places that must stay in sync: `style.css`, `client/src/features/theme/theme.ts` (`PRESETS`), `client/public/js/theme-boot.js` and `src/controllers/themeController.js` (`PRESETS`).
- `theme-boot.js` is a classic (non-module) script in every page's `<head>`. It applies the cached theme before first paint; `features/theme/theme.ts` reuses it via `window.mbsApplyTheme`. The theme is saved per account (`users.theme` JSONB) and returned at login.
